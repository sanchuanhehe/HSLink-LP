# 上游固件采样相位与电平转换复核

2026-11-07。按 `upstream.lock.json` 锁定的 CherryDAP
`67fb4b5412772a6a435e5f02f694f1615f0b5030` 与 HPM SDK v1.9.0
`d64c133d0626a6986125f33c2e3f9283c7088e88` 分析。需求仍以
[requirements.md](requirements.md) 为准，SWD/JTAG 40 MHz 目标不变。
本次是源代码、协议和数据手册复核，没有编译后的指令周期测量或实板测试。

## 修正结论

此前把 SWD 目标数据更新当作下降沿，套用 12.5 ns 半周期预算，结论有误。
锁定版本的高速 SWD 是 SPI Mode 0；目标在上升沿更新数据，探针在下一上升沿读到上一拍数据，连续读回可利用约一个周期（40 MHz 时 25 ns）。
这解释了 SN74LVC1T45 与高速 SWD 在原理上并不矛盾。
另外，不能仅凭 DIR→A 的 27.6 ns 大于 25 ns 就判断换向必然失败。

不过，上游源码和产品最高频率说明不构成本板 1.8 V、FSA、具体线缆负载下的保证。
全单路 DBVR 改列为**优先验证候选**；八路 LVC 负责时钟的混合方案优先级较低。
当前未找到能闭合完整 1.8～3.3 V／SWD 和 JTAG 40 MHz 要求的证据，故本次不修改器件和电气连接，也不将候选收益计入已实现降本。
原 LXC 的最坏延迟并不优于全单路 LVC，保留现状不能解释为“贵的才能跑 40 MHz”。

尤其 boost 路径中 `_freq` 在乘十前保存，后续最近频率选择仍使用它，本次不把文档的“乘十”当作已验证实际频率。

不能据此倒推 1.8 V 的全条件保证，也不能认定上游只能在 3.3 V 工作。

## SPI 模式的连续 SWD 读回

`SW_DP_SPI.c:396–406` 设置 CPOL=0、CPHA=0、LSB first、MOSIBIDIR=1。
SDK `hpm_spi_regs.h:140–164` 明确为低电平空闲、奇数边沿采样，因此采样边沿为上升沿。
数据段直接写入 `TRANSFMT=0x1f18`（该文件 237–239 行），CPOL/CPHA 仍为 0，没有暗中改到下降沿。

ARM IHI0031D §B4.3.1 规定目标在上升沿接收、更新或释放 SWDIO；
ARM DSTREAM 指南 §3.5 也给出目标上升沿更新、探针上升沿读取的实现。
对连续数据位，相位关系如下，时间从 MCU 的 SWCLK 输出焊盘计：

```text
MCU SWCLK       ↑ k             ↓              ↑ k+1
时间            0              12.5 ns          25 ns
目标 SWCLK        ↑ k（经过时钟通路延迟）
目标 SWDIO          bit k（再经过目标输出延迟）
MCU SWDIO              bit k（再经过返回通路延迟）
SPI 采样         bit k-1                         bit k
```

实际检查应满足：

```text
时钟转换器上升沿延迟 + 时钟侧 FSA/走线/线缆延迟
+ 目标 SWCLK→SWDIO 最大延迟 + 返回侧 FSA/走线/线缆/转换器延迟
+ HPM 输入建立时间 + 周期抖动裕量 <= T
```

同时检查输入保持时间、目标端高低脉宽和输出阈值。不能把两方向最大值的和解释为同一颗实物必然出现的延迟；它是在缺乏相关性保证时采用的保守上界。

`SPIACTIVE` 等待和 CPU 读取 DATA 寄存器发生在硬件采样之后；它们不会延后 32 位段内部每一位的采样点。
`dummy` 是接收数据变量，初始化的 `spi_trans_write_dummy_read` 随后被实际读写模式覆盖，不是额外一个周期的数据采样补偿。
GPIO 的 `LOOP_BACK` 在 SDK IOC 定义中只表示强制打开引脚输入，并未提供目标端返回时钟，不能按其名称增加一周期预算。
MOSIBIDIR=1 使用双向 MOSI；不能因为原理图另有 MISO 电阻支路就声称在该 SPI 路径用 MISO 独立相移采样。

## SWDIO 换向逐段核对

令 `n = DAP_Data.swd_conf.turnaround`。DAP 初始化为 1；`DAP.c:482–488` 把主机配置转换为 1～4，函数本身不会替目标写 DLCR。

|阶段|上游实际顺序|时序含义|
|---|---|---|
|请求→ACK，`SW_DP_SPI.c:205–231`|DIR=1；写 8 位请求；等 SPIACTIVE 清零；DIR=0；改读模式与位宽；发 CMD；读取 ACK 并右移 n|读请求接收 n+3 位，写请求接收 n+3+n 位；最前 n 位是 turnaround 丢弃值，首个有效 ACK 不是 DIR 改变后立即采样|
|ACK→读数据，234–251 行|保持 DIR=0，依次读取 32 位和 1 位校验|分段有软件间隔，32 位内部是连续时钟；分段间隔不能放宽所有数据位的预算|
|写 ACK→写数据，215、275–285 行|ACK 接收段已含末尾 n 个 turnaround；再 DIR=1、配置写模式、写 32 位和校验|需要查 MCU MOSI 的输出接管与外部转换器 A 端释放之间是否冲突|
|读校验→恢复输出，252–264 行|等校验段结束后，先 DIR=1，再用写模式产生 n 个 turnaround 时钟|与 GPIO 路径先完成空拍再使能输出的顺序不同；必须核对目标释放边沿及外部转换器真正开始驱动的时刻|
|WAIT/FAULT，313–355 行|有专门的数据阶段和 turnaround 分支|不能只测试 OK；异常路径的位数、总线释放和恢复输出也要覆盖|

若 `g` 表示 DIR 下降到第一个接收采样沿的实际间隔，首个有效 ACK 采样约发生在 `g+nT`，还要扣除输入建立时间。
因此 `27.6 ns > 25 ns` **不能单独否定读取使能**；需验证 `g+nT` 的下界。
然而 B 端的关闭必须早于目标开始驱动，不能借用后面的 ACK 采样时间来证明总线不会争用。
源码中的几次寄存器访问和 CS 建立间隔不能凭源代码行数换算成有保证的 ns。

本次没有上游构建的反汇编或 DIR/SWCLK/SWDIO 波形，不能把这些间隔写成确定的“几十/几百 ns”。
特别是读完或错误路径中 DIR 提前恢复为输出，以及切回写模式前转换器 A 端还可能驱动的短暂区间，需分别看目标侧和 MCU 侧。
这不是已经证实上游存在冲突，而是缺少时序证据的检查点。

LP 固件应明确实现：请求末位保持完成后释放 MCU 输出与目标输出驱动；留出关闭/建立保护时间；执行协议所需的空拍；确认目标释放后再接管。
可在合法的阶段边界保留软件间隔，但不能随意多加 SWCLK，也不能仅把探针 turnaround 改成 2 就认为目标同步改变了协议。
所有保护时间需用所选器件最大值、MCU 外设接管语义和编译/波形证据定界；本次未将它写成已实现功能。

## GPIO 与 JTAG 必须分开

GPIO SWD 的 `SW_DP_IO.c:50–55` 是拉低 SWCLK、等待、读输入、再拉高 SWCLK。
被读数据由**前一次上升沿**触发，所以也不是“刚拉低后等待半周期完成目标输出”的模型。
时钟宏、GPIO 访问、fence、循环运算都影响实际周期；DAP 请求 40 MHz 不代表这条路径实测就是 40 MHz。

JTAG 的 SPI 设置同为 Mode 0（`JTAG_DP_SPI.c:725–735`），但目标 TDO 通常在 **TCK 下降沿**更新。
因此连续 JTAG TDO 读回才是下降沿到下一上升沿的半周期预算，不能直接复制 SWD 的整周期结论。
单比特路径还使用 GPIO（254–296 行），多比特使用 SPI（299 行起），需两条都测。
该上游没有在这些函数中实现可量化的目标时钟返回补偿或独立可调采样相位。

## 按实际窗口重算

TI 的 SN74LVC1T45 SCES515N §5.8、SN74LVC8T245 SCES584D §5.9 使用规定的 15 pF 测试负载，
不能把增加 FSA 后的实际负载仍视为 15 pF，也不能线性缩放手册最大延迟。
官方 [HPM5300 Rev0.11](https://www.hpmicro.com/Public/Uploads/uploadfile/files/20250205/HPM5300DSV011.pdf)
§4.13.1／表 39（印刷页 63–64，PDF 页 66–67）要求 SPI 主模式输入建立时间至少 10 ns、保持时间至少 2 ns；不能套用下一张从模式表的 2.7 ns。

下表只做 SWD 连续读回的上界筛选。负余量表示手册不能证明通过，**不是实物必然失败**。
手册使用其规定温度范围，并非用户已确认全温验收；室温实测值仍需另取证据。

|电平和方案|时钟上升 A→B + 返回 B→A 上界|加 HPM 10 ns 建立时间|距 25 ns 剩余|
|---|---:|---:|---:|
|1.8 V：LVC8＋LVC1|21.2+8.3=29.5 ns|39.5 ns|−14.5 ns|
|1.8 V：全 LVC1|15.5+8.3=23.8 ns|33.8 ns|−8.8 ns|
|2.5 V：全 LVC1|8.0+6.4=14.4 ns|24.4 ns|0.6 ns|
|3.3 V：全 LVC1|5.8+5.8=11.6 ns|21.6 ns|3.4 ns|
|1.8 V：原 LXC|15+16=31 ns|41 ns|−16 ns|

表内尚未包括目标输出延迟、FSA、线缆、负载超出测试条件、抖动裕量。
正数也不是通过，尤其不能把 3.4 ns 全部当作可用线缆裕量。
JTAG 使用时钟下降沿的 tPHL；例如全 LVC1 在 1.8 V 为 `12.6+8.3+10=30.9 ns`，已超过 12.5 ns，且尚未计目标和 FSA。

主控→目标的写出不是把两路延迟相加：应比较数据路径最大值与时钟路径最小值的偏差，再叠加 HPM 输出有效延迟（表 39 最大 8 ns）、目标建立/保持时间及 PCB 偏差。
相同型号器件有助于实际匹配，但单独封装之间没有可凭空使用的零偏差保证。还要检查交替比特和时钟脉宽失真，不能用一次静态跳变延迟代替持续时钟验证。

## 本轮采用决定与下一步

用户已确认按 12 颗 SN74LVC1T45DBVR 落实打样原理图，保持 40 MHz 验收目标并明确待实测。该决定不改变上述尚未闭合的最坏预算，也不代表量产或硬件性能通过。混合 LVC8 方案不采用；原 LXC 只保留为历史基线。

原理图、封装分配、偏置、BOM 和价格已在后续实施中更新，完整费用见 [电平转换说明](level-translation.md)。旧简化候选费用未包含偏置和全板去耦阶梯变化，已不作为当前成本结论。

下一轮前置验证优先使用全 DBVR＋真实 FSA 链路，并与原版探针在相同目标上对照：

- 记录芯片批次、固件 SHA/构建参数、目标型号及其允许调试时钟；1.8/2.5/3.3 V、约定温度、实际线缆和探头负载分别记录。
- 同测 MCU 侧 SWCLK、目标侧 SWCLK、目标 SWDIO 与 MCU 返回输入，确认每个有效数据位在采样前的建立时间和采样后的保持时间；不能只报告“下载成功”。
- 测 DIR 与两侧驱动交接，覆盖读→写、写→读、OK/WAIT/FAULT、连续 AP 读取、校验、复位和重连；区分段间暂停与段内 40 MHz。
- 单独测试 JTAG 连续移位与单比特/TMS 路径；保留固定 40 MHz 验收目标，记录失败频率作诊断，不能以自动降速当作通过。
- 若 1.8 V 或 JTAG 时序不够，先评估有数据支持的采样相位实现或仅加强调试通道；双 UART 可继续采用低成本转换，重新计算完整费用。
- 保留 FSA、复位隔离、VIO 独立供电和测量锁；所有调压/方向配置流程都不得隐式解除测量断开。
